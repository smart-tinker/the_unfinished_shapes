# Contributing

1. Open one GitHub issue per feature or bug, with acceptance criteria and scope.
2. Implement each issue in its own branch; keep commits issue-scoped.
3. Open a PR against the current release branch. Review and merge sequentially after required checks pass.
4. Use the public repository's standard free GitHub-hosted runners. Do not enable paid runners, broader permissions, signing services or unsafe runtime options without an explicit decision.
5. Keep secrets and user data out of code, issues, logs and release assets. Do not copy private project material into this public repository.

For the authoritative release lifecycle, version/tag rules, current workflow behavior, release gates and failure handling, see [docs/RELEASING.md](docs/RELEASING.md). Runner allocation and CI scenarios are in [docs/CI.md](docs/CI.md).
